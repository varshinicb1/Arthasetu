You are a senior fintech systems architect and full-stack engineer.

Build a COMPLETE working prototype of a fintech system called:

**ArthaSetu – Merchant Assurance Layer (MAL)**

This is NOT an offline banking system. It is a **merchant-side decision engine for uncertain or failed digital payments**.

The system must simulate how merchants can **accept or reject payments based on confidence scoring when network/bank confirmation is unavailable**.

---

# 🧠 CORE IDEA

When a payment is attempted:

* It may not be confirmed (network failure)
* Instead of failing, the system:

  1. captures transaction intent
  2. generates a verifiable proof
  3. calculates a risk/confidence score
  4. allows merchant to decide

---

* Python Flask API

* JSON-based (simulate DB)

* WebSockets (if easy)

## 2️⃣ TRANSACTION CREATION

Customer enters:

* amount
* merchant

System generates:

{
txn_id,
amount,
customer_id,
merchant_id,
timestamp,
status: "PENDING"
}

---

## 3️⃣ LOCAL PROOF GENERATION (IMPORTANT)

Simulate a cryptographic proof:

signature = hash(txn_id + amount + timestamp)

Attach this to transaction.

Display it in UI as:

"Transaction Proof Generated"

---

## 4️⃣ NETWORK SIMULATION

Add toggle:

* ONLINE
* OFFLINE

Behavior:

OFFLINE:

* no backend confirmation
* transaction remains "UNCONFIRMED"

ONLINE:

* allow sync
* mark transaction as SUCCESS/FAILED

---

## 5️⃣ RISK / CONFIDENCE ENGINE (CORE FEATURE)

Create function:

risk_score(txn, user_behavior)

Rules:

* small amount → +20
* repeat user → +20
* frequent transactions → -30
* suspicious pattern → -40

Final score between 0–100

Display:

* 80–100 → HIGH CONFIDENCE (green)
* 50–79 → MEDIUM (yellow)
* <50 → LOW (red)

---

## 6️⃣ MERCHANT DECISION PANEL

Merchant sees:

* incoming transaction
* amount
* status: UNCONFIRMED
* confidence score

Options:

✔ Accept Payment
⚠ Accept with Risk
❌ Reject

Store merchant decision.

---

## 7️⃣ FRAUD SIMULATION

Add buttons:

* “Simulate Double Attempt”
* “Simulate Rapid Transactions”
* “Simulate Fake Retry”

System should:

* reduce confidence score
* show alert
* log event

---

## 8️⃣ SYNC ENGINE

When ONLINE:

* send all pending transactions to backend
* randomly mark:

SUCCESS or FAILED

Update UI.

## 9️⃣ LOGGING SYSTEM
